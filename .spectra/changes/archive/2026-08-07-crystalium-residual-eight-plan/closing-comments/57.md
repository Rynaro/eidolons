**Closed — FIXED in v2.0.2.**

`mcp-server/tests/test_server_entrypoint.py::test_serve_stdio_handshake` launches
`python -m crystalium serve` as a real subprocess and speaks raw JSON-RPC over stdio
(`initialize` → `notifications/initialized` → `tools/list`), asserts a non-empty tool list
containing a live-read single-segment tool name, then closes stdin and asserts a clean exit.

Two properties this was built to have, both red-checked:
- **A startup crash is visible, not swallowed.** `stderr=subprocess.PIPE` (never `DEVNULL`) and
  the captured stderr is folded into every assertion message. Red-check: injecting
  `raise NameError` at the top of `run_stdio` fails the node with the traceback surfaced.
- **The handshake is genuinely parsed, not merely "the process didn't crash."** Red-check:
  asserting a nonexistent tool name fails the node, with the real advertised tool list in the
  failure output.

Not marked `slow`, deliberately: the handshake needs no model, so it runs under `make test-ci`
(`CRYSTALIUM_SKIP_SLOW=1` with slow tests still selected) — the mode CI actually runs. A
`slow` mark would have left CI exactly as unprotected as before.

`serverInfo.version` is deliberately never asserted: `__version__` derives from installed
package METADATA, so under a bind mount it reports the image's version, not the source's.

**Not covered, recorded rather than glossed:** `run_http`'s uvicorn startup and port binding.
`build_http_app`'s ASGI construction and the Streamable-HTTP request path are already covered
in-process by `test_server.py`. A flaky ephemeral-port test would have been worse than a
recorded gap.

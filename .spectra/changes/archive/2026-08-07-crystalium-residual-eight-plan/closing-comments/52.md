**Closed — FIXED in v2.0.2.**

Confirmed exactly as reported: the shipped `cross_layer` axis called `bm25_search` directly,
never reached `Aetheryte.recall`, and the fixture pinned both values at `0`. Measured on
v2.0.1: `cross_layer: {"episodic": 0, "semantic": 0}`. It could not fail.

**Two parts, both shipped:**

1. **The axis is relabelled, not silently deleted.** `cross_layer` →
   `sparse_arm_per_layer_probe` in `evals/fusion_gate.py`, with the AC-126 docstring rewritten
   to say what it actually measures — a per-layer `bm25_search` sanity probe. The historical
   record survives.
2. **A real gate replaces it:** `evals/cross_layer_gate.py`, driven **through
   `Aetheryte.recall`**. It shipped RED as a strict xfail citing #45 and is now GREEN
   (see #45).

**The gate attributes rather than merely detects.** Its liveness object asserts the pinned
axes non-binding *before* emitting any number, and includes a global-BM25 probe: the target is
rank 0 across all layers while fusing at rank 3. Global rank 0 + fused rank 3, with the dense
arm empty, the graph edgeless and completion off, can only be layer-append order.

One correction to the original plan worth recording: the first fixture design used episodic
fillers carrying "one query term each". That is unbuildable here — FTS5 in the pinned build
(sqlite 3.46.1) is **implicit-AND**, so a crystal matching a strict subset of the query terms
does not match at all. The fillers would have matched nothing, leaving the target alone at
rank 0 and the gate GREEN — a gate that could not fail on the defect it names, which is this
issue's own complaint. The shipped fixture separates by term frequency and document length
instead, and asserts `sparse_arm_size == corpus_per_layer + 1` so a filler silently failing to
match reddens the gate.

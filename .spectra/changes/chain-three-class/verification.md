## Remediation (shipped as v2.19.1)

- **Coverage test corrected to subset semantics** in `cli/tests/routing_chains.bats`:
  a pair is resolved iff some `C` has `C.req ⊆ (A ∪ B)` **and** `|C| > |A|`.
  This closes F1 and F3 with one fix — duplicate class sets now surface as
  unresolved automatically, because no strict superset can exist inside their
  own union.
- **Pinned set corrected 7 → 5**, and the newly-visible fact recorded: this
  change *resolved* a pre-existing tie (`ship-fast` vs `forensic-then-fix`),
  moving the set 6 → 5.
- **`scout-diagnose-plan-fix` now ends in `idg`**, restoring the scriber step
  that `plan-before-build` carried. New test: *"the widest pipeline does not
  drop the scriber step"*.
- **New regression test** feeding the corrected helper a roster with a
  duplicate class set and asserting it surfaces — the falsifying case for the
  pin itself.
- Corrections propagated to `roster/routing.yaml`, `methodology/cortex/chain-templates.md`,
  `CHANGELOG.md` (the v2.19.0 entry is annotated in place, not rewritten), and
  this record.

## What this round cost, and why it was worth it

The change shipped as v2.19.0 with a green suite, a mutation-falsified test
set, and a written claim that its own invariant had been audited. All three
were true, and the invariant was still wrong — because the audit reused the
instrument it was auditing. Nothing short of a distinct actor re-deriving the
property from the kernel would have caught it.

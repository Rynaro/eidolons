# Phase 4 — Methodology and ecosystem adaptation

Entry: Phase 3's first managed path is accepted. Exit: required G11–G15 slices are accepted with explicit compatibility evidence; optional clients remain optional. G11, G12, and G14 can start in separate repository/worktree lanes after G10. [plan.yaml](plan.yaml) owns the remaining dependencies. These packages change methodology, not merely host prompts, and remain individually switchable pending Phase 5. Read [HANDOFF.md](HANDOFF.md).

## G11 — Make RAMZA-lite economical and consumable

**Primary repository:** Rynaro/Ramza. Start with `SPEC.md`, `PERSONA.md`, `tiers.md`, `skills/`, the scoring/gate tools actually present, and templates. Nexus adoption occurs only after the member's tested release is authorized/published. Depends on G10.

Add an explicitly versioned lean planning mode for clear, reversible, known-pattern work. The minimum result is outcome, scope/non-goals, acceptance and verification, selected approach, consequential assumptions/risks, and an actionable handoff. Do not require three-to-five invented alternatives, repeated decompositions, or full hierarchy templates when they provide no decision value. Preserve deeper analysis for real competing options, unclear outcomes, security boundaries, migrations, or other consequential uncertainty.

Right-sizing is still observable and inspectable. Do not infer low risk solely from few changed files. Deterministic scoring of model-supplied rubric values is not calibrated success probability; name heuristic scores honestly. Clarification occurs when a missing answer changes required behavior or authority, not to complete a template. Necessary uncertainty remains visible rather than guessed away.

Pass settled decisions and reusable evidence to the maker so it need not redo the same analysis. Respect the current output schema and authority contract; required changes need explicit producer-side revisions. A lean mode must not silently violate the current specification, erase rejected consequential alternatives, or alter the full-tier protections.

| Acceptance | Required verification |
|---|---|
| G11-A1: A clear conventional lite task produces the minimal actionable contract without manufactured alternatives. | Frozen task fixtures compare required semantic fields, dependencies, and verifier coverage. |
| G11-A2: Consequential uncertainty still selects sufficient planning/clarification. | Small-file security change, migration, ambiguous product choice, and competing-pattern controls. |
| G11-A3: The maker consumes settled decisions without a required duplicate strategy search. | Producer/consumer handoff fixture through the actual validator and a candidate-maker invocation. |
| G11-A4: Scores and completion language do not claim unsupported probabilities or verification. | Output/schema assertions plus a genuinely separate review of the semantic fixtures. |
| G11-A5: Legacy/full behavior and standalone installation remain compatible. | Existing member conformance/gates and no-Gauge fixtures; lean behavior remains explicit opt-in. |

**Stop/rollback:** no weakening full-tier authority or new scoring research campaign. Preserve the previous methodology mode and leave default changes to G18.

## G12 — Explicit Vivi delivery authority and continuity experiment

**Primary repository:** Rynaro/Vivi. Start with `SPEC.md`, `PERSONA.md`, `skills/loop-native/SKILL.md`, planning/failure-recovery/context skills, templates, and existing loop fixtures. Depends on G10; does not require G11 to start.

Introduce a versioned execution-mode contract separating candidate generation, authorized application inside an isolated worktree, and publication. Preserve proposal-only as a supported mode. Worktree application requires an explicit parent/operator grant; Gauge presets cannot grant it. Do not interpret an implementation request as permission to merge, push, release, deploy, or touch unrelated files. Retain protected acceptance/test anchors, current-candidate verification, lint-before-slower-tests, and bounded recovery.

Add a candidate continuity mode for a coherent task: maintain one maker context, preserve failed approaches, and reset only for a recorded reason such as measured context pressure or no-progress evidence. Keep fresh repair attempts available as the control. This revises the current fresh-context invariant only through a named opt-in methodology amendment, not by ignoring it. The checker remains a separate invocation/context with an explicitly observed separation grade. Do not assume warm retries outperform fresh retries; G17 evaluates that question.

When a valid upstream decision exists, consume it and plan only the execution details still unresolved. Integrate the shared remaining budget and failure categories from Phase 3; an escalation never creates new allowance. A greenfield request continues to follow the existing refusal/explicit bootstrap boundary; greenfield expansion is a separate proposal, not hidden in this package.

| Acceptance | Required verification |
|---|---|
| G12-A1: Application requires the exact scoped authority; presets and model output cannot widen it. | Proposal-only control, authorized isolated application, real-tree escape, publish/deploy attempts, and unrelated dirty files. |
| G12-A2: Continuity preserves relevant decisions/failures while the checker remains separate. | Instrumented iterative task and reset/handoff case; capture actual context access, not merely actor labels. |
| G12-A3: Both continuity and fresh modes remain selectable under identical acceptance and budgets. | Matched fixtures with protected tests, repeated-failure stop, and shared-accounting assertions. |
| G12-A4: The loop cannot game completion by editing anchors or reporting a stale green candidate. | Anchor edits, skipped tests, acceptance mutation, and post-check changes each remain non-success. |
| G12-A5: Existing standalone/proposal-only behavior remains supported. | Member conformance and host-degradation cases; no automatic default switch. |

**Stop/rollback:** no claim of improved completion until G17; no autonomous architecture/deployment expansion. Disable continuity/application mode without losing candidate patches, evidence, or reservations.

## G14 — Context and retrieval economy without losing task state

**Primary repository:** Rynaro/eidolons. Depends on G10. Start with actual host prompt assembly, context policy/pins, checkpoint and memory preflight code, `cli/src/harness_hook.sh`, and token-budget tests. Follow with targeted sibling slices only where needed: ECM/atomos for succession contracts, atlas-aci for revision-valid retrieval, CRYSTALIUM for memory selection, and optional Magicite integration.

Measure actual instructions/tool schemas injected by the host, repeated prompt additions, tool-result volume, retrieval latency, indexing/startup time, and reconstruction after compaction. File-marker token checks are useful but do not establish the full prompt cost. Keep observed counts distinct from tokenizer/bytes-based estimates. Do not promise to 'unload' text from an append-only native transcript; reduce future duplication or use supported context succession instead.

Build a task-scoped evidence pack once and reuse it while its repository/criteria/environment dependencies remain valid. Retrieve changed or newly relevant regions, retain full logs outside working context, and deliver bounded failure excerpts with stable references. Do not truncate required instructions or silently drop acceptance evidence. Deduplicate memory preflights only when query/scope/state validity makes reuse safe; incompatible memory must not be treated as authoritative just because it is cheap.

Add hysteresis/debounce to repeated context actions only with observed triggers, state transitions, and tests; preserve operator-configured ECM policy. Preserve stable prompt prefixes where the host actually supports them and report cache/reconstruction costs rather than assuming fewer characters always save quota. Sibling changes must preserve trust propagation, quarantine, project isolation, active-revision selection, and compose/verify parity. Atomos must not acquire policy/metering or a durable-memory role. Magicite remains optional progressive skill selection, not a mandatory extra routing hop.

| Acceptance | Required verification |
|---|---|
| G14-A1: Measured prompt/injection overhead reflects the actual supported host path. | Captured fixture/native assembly comparison, repeated-turn payloads, tool-schema accounting, and explicit unknown fields. |
| G14-A2: Reused evidence is invalidated by relevant changes, not unrelated churn. | Code/criteria/environment mutations plus an unrelated-file control; current anchors and missing artifact checks. |
| G14-A3: Compaction/succession retains mandatory pins, pending checks, failures, and remaining allowance. | Context-pressure fixture and cold/warm resume with missing or stale memory. |
| G14-A4: Bounded output is useful and full evidence remains accessible. | Large failure log with crucial assertion outside the tail; truncated display references complete redacted evidence. |
| G14-A5: Optional-server absence and repeated triggers do not cause storms or hidden authority changes. | No-MCP path, failed recall, rapid prompts, concurrent hooks, repeated-zone transitions, and foreign-project content. |

**Stop/rollback:** no new memory engine, mandatory container, changed trust model, speculative universal compaction threshold, or unmeasured savings claim. Turn optimizations off independently; preserve saved state and exact verification evidence.

## G15 — Accessible CLI status and optional client presentation

**Primary repository:** Rynaro/eidolons; optional public client slice: Rynaro/GAMBIT. Depends on G13 and G14. External/private client adapters are separate opt-in assignments outside this public campaign; do not publish private code, paths, credentials, or screenshots here.

Expose the shared policy/status/receipt as a versioned machine interface with a terminal-readable view. Show persistent preset, origin, enforcement granularity, observation freshness, actual model when known, remaining local allowance/reserve in its unit, observable delivery milestone, next action, and whether a specific human decision is needed. No fabricated provider quota or completion percentage. A cosmetic Gauge bar cannot substitute for G07/G08 enforcement.

Keep Conserve/Balanced/Accelerate understandable in plain language; label FF flavor as secondary to purpose. Avoid color-only warnings, tiny text, or a GUI requirement. Let users inspect why the route is expensive and what remains unsupported without requiring them to learn every contract acronym. A policy-change preview is local and does not dispatch models or raise ceilings.

GAMBIT consumes the nexus interface rather than duplicating budget logic; any native launch outside managed control is labeled accordingly. Private/other clients can consume the same documented interface, but their availability does not block a working CLI release. Preserve host credentials and native sessions in their existing owners.

| Acceptance | Required verification |
|---|---|
| G15-A1: CLI/JSON present the same current policy and evidence state. | Snapshot/contract fixtures for managed, monitored, advisory, unknown/stale quota, partial, blocked, and cancelled cases. |
| G15-A2: Presentation never grants authority or causes a model request by inspection alone. | Preview/status/set tests, boundary fixtures, and mock dispatch counters. |
| G15-A3: The terminal flow works without a GUI or any optional MCP. | Clean opt-in/opt-out installation and headless smoke path. |
| G15-A4: Optional clients honor protocol versions and truthful enforcement labels. | Consumer contract tests; client launch outside managed control remains visibly ungoverned. |
| G15-A5: Users can identify the setting, current limitation, next action, and blocker without color dependence. | Keyboard/plain-text/no-color review and a documented usability walkthrough. |

**Phase 4 exit:** core slices accepted and independently switchable; optional client slices explicitly included or deferred before evaluation. Their deferral cannot disguise missing core policy, accounting, execution, or terminal accessibility.

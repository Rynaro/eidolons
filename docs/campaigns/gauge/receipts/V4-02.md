## Delivered behavior and recovery boundary

[DECISION] Remove pre-inspection metadata healing so checks remain observational. Distinguish tracked changes, including `.gitignore` and all four installation sidecars, from untracked root sidecars; refuse when Git inspection fails. Existing refresh-managed roster, `EIDOLONS.md`, and `methodology/cortex` exclusions remain. The historical `nexus_ensure_gitignore_sidecar` helper now writes root-anchored Git `info/exclude` entries, never tracked `.gitignore`.

Refresh still backfills a missing `.roster_ref` from the environment or `main`. Upgrade writes metadata only in the validated staged clone, carrying existing `.roster_ref` bytes exactly or creating it there from the environment or `main`. No force or integrity bypass is needed. Linked-worktree and separate-Git-directory replacement/rollback are explicitly rejected; safe checks remain available. Source behavior in this section is from the maker/root handoff and checker acceptance described below.

The [CLI recovery instructions](../../../cli-reference.md#legacy-installation-recovery) invoke patched `cli/src/upgrade_self.sh` directly from a trusted source checkout, with matching `EIDOLONS_HOME` and `EIDOLONS_NEXUS` pointing at an old standalone installation. A modern dispatcher still selects the old installed updater. This is not retroactive repair of old executables. Existing tracked changes, including installer-appended `.roster_ref` lines in `.gitignore`, are preserved and refused; users review and deliberately commit or stash them before retrying.

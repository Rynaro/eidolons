## Delivered contract

[DECISION] Keep schema 2. Add typed calibration namespaces (`calibration_trials`, `calibration_baselines`, `calibration_arms`, `calibration_batches`, `calibration_costs`, `calibration_promotions`, `calibration_boundaries`, `calibration_decisions`, `calibration_adaptations`, `calibration_generalizations`, `calibration_strategies`, `calibration_offline`, `calibration_events`) with `meta.calibration_receipt` and typed version guards. Extends V4-21 evaluation — does not replace it. Ablate one mechanism at a time; missing mechanism packages (V4-10/16/17/18/19) stay **pending/ineligible**, not fabricated zeros. Calibration uses only development/calibration data with freeze-before-holdout chronology. Benefit claims require complete coordination/reconstruction/integration/rebuild costs. Null/inconclusive/no-win/regression/incomplete-cost leave mechanisms unpromoted with no default flip and no post-outcome oracle changes. Trial boundaries stop further dispatch on overspend/unknown exposure/authority/late usage while retaining partial data. Adaptive decisions bind action to observed state, allowed alternatives, policy version, and reason (observation≠estimate; no hidden reasoning). Experience-derived adaptations carry evidence sources, scope, parent version, rollback target, and immutable diff; failed/stale/self-attested experience cannot become an active rule. Same-batch improvement is labeled adaptation; forward generalization requires frozen candidate + compute-matched control. Promoted strategies bind model/harness/task scope and revalidation; distribution changes invalidate affected claims. Optional offline adaptation isolates proposals from active policy/oracle/live controller in a sandbox and cannot self-approve promotion.

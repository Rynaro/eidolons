## Delivered contract

[DECISION] Keep schema 2. Add typed acceptance namespaces (`frozen_candidates`, `acceptance_packages`, `check_receipts`, `oracle_qualifications`, `owner_reviews`, `definition_blockers`, `protected_paths`) with `meta.acceptance_receipt` and typed version guards. Mandatory verification binds to a frozen candidate content digest covering tracked/untracked/config/mode entries plus acceptance and environment identities; concurrent maker edits produce distinct digests while check logs identify the exact snapshot tested. While candidate execution is active, an enforceable isolation fixture (`chmod` deny on protected journal/receipt/oracle/key paths, write allowlist for candidate/build, filtered env that strips checker/signer credentials) denies authoritative writes — label-only and directory-without-enforcement are not positive controls. Runner finish records observed outcomes (`pass`/`fail`/`error`/`cancelled`/`skipped`) with invocation provenance; authored success prose cannot replace observation. Missing enforced isolation or context provenance withholds the trusted integrity grade. Target-base movement, dirty targets, and post-green conflicts require revalidation before application. Human report projection preserves distinct integrity, provenance, and acceptance fields; digest equality does not authenticate authors or prove semantic correctness. Oracle qualification requires discrimination on known-valid plus representative stub, missing-edge, and regression fixtures — inadequate discrimination prevents qualification. Maker changes to required tests/verification definitions need recorded acceptance-owner review; maker approval alone is insufficient and old evidence is invalidated. Observable application behavior must execute in the declared environment before accept; unit-only and fabricated-log candidates fail the behavior gate. Ambiguous brief/oracle or missing behavioral discriminator yields an acceptance-definition blocker with no silent requirement invention or weakening.

Zero real network. Live qualification remains fail-closed (V4-09). Mutators retain append lock + active claim/inventory checks. Bash 3.2 legacy CLI unchanged; acceptance commands are opt-in Go only. No universal correctness claim, no new custom test framework, no auto push/merge/release. No V4-15+.
